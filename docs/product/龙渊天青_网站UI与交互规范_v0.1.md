# 一、设计总纲

## 1.1 设计定位

龙渊天青网站不采用常见AI网站的“蓝紫渐变、发光粒子、科技大屏”视觉。

前台设计关键词：

> **现代、克制、温润、可信、东方但不仿古。**

后台设计关键词：

> **清晰、可审计、高信息密度、状态优先。**

网站视觉必须同时完成两件事：

1. 让外部用户相信这是一家真实生产作品的文化公司；
2. 让内部参与者和管理者清楚地完成任务、验收和裁决。

## 1.2 前台与后台的视觉分工

| 区域 | 核心目标 | 视觉原则 |
|---|---|---|
| 前台 | 建立品牌、展示作品、吸引参与 | 留白、克制、编辑感 |
| 参与者中心 | 完成任务 | 状态明确、操作路径短 |
| 管理后台 | 审核、裁决、查询、追踪 | 信息密度高、证据并列 |
| Agent页面 | 展示运行、版本、证据与候选 | 禁止拟人化，强调可追溯性 |

# 二、品牌视觉系统

## 2.1 色彩Token

### 基础色

| Token | 色值 | 用途 |
|---|---:|---|
| `--color-bg` | `#F5F7F3` | 页面背景，近瓷白 |
| `--color-surface` | `#FFFFFF` | 卡片、表格、输入区域 |
| `--color-text` | `#1C2421` | 主文字 |
| `--color-text-muted` | `#66716C` | 次级信息 |
| `--color-border` | `#D7DED9` | 边框、分割线 |

### 品牌色

| Token | 色值 | 用途 |
|---|---:|---|
| `--color-celadon-900` | `#17322D` | 主按钮、页头、重点标题 |
| `--color-celadon-700` | `#345A4F` | 次级按钮、链接 |
| `--color-celadon-500` | `#6E9283` | 标签、辅助图形 |
| `--color-celadon-200` | `#C9D9D1` | 浅背景、选中态 |
| `--color-celadon-100` | `#E7EFEB` | 大面积柔和背景 |

### 窑火强调色

| Token | 色值 | 用途 |
|---|---:|---|
| `--color-kiln-700` | `#8C4A2D` | 高风险提醒、重要裁决 |
| `--color-kiln-500` | `#B86A3B` | 小面积强调 |
| `--color-kiln-100` | `#F3E5DC` | 提醒背景 |

窑火色只能用于：

- 高风险；
- 返工；
- 冲突；
- 需要人工裁决；
- 少量品牌强调。

不得用于大面积背景或常规按钮。

### 状态色

| 状态 | 色值 | 用途 |
|---|---:|---|
| 成功 | `#2F6A4F` | 已通过、已完成 |
| 提醒 | `#9A6A25` | 待审核、临近截止 |
| 风险 | `#9D3E32` | 驳回、失败、超限 |
| 信息 | `#3F6382` | 处理中、Agent运行 |
| 中性 | `#69736F` | 草稿、暂停、归档 |

## 2.2 色彩纪律

不得出现：

- 蓝紫AI渐变；
- 霓虹色；
- 黑底荧光绿；
- 大面积红色；
- 无语义的多色标签；
- 每张卡片一个颜色。

同一种状态在全站必须使用同一套颜色和文案。

# 三、字体与排版

## 3.1 字体

首期不引入自托管字体文件。

推荐字体栈：

```css
font-family:
  "Noto Serif SC",
  "Source Han Serif SC",
  "Songti SC",
  serif;
```

用于：

- 首页主标题；
- 书名；
- 大段品牌叙述；
- 公司介绍标题。

正文与工作界面：

```css
font-family:
  Inter,
  "Noto Sans SC",
  "Microsoft YaHei",
  sans-serif;
```

用于：

- 导航；
- 任务信息；
- 表格；
- 表单；
- 后台；
- 状态标签。

## 3.2 字号层级

| 层级 | 桌面端 | 移动端 | 用途 |
|---|---:|---:|---|
| Display | 56px | 38px | 首页主标题 |
| H1 | 40px | 30px | 页面标题 |
| H2 | 30px | 24px | 章节标题 |
| H3 | 22px | 20px | 卡片组标题 |
| Body Large | 18px | 17px | 品牌说明 |
| Body | 16px | 16px | 正文 |
| Small | 14px | 14px | 次级信息 |
| Caption | 12px | 12px | 时间、版本、辅助信息 |

## 3.3 排版纪律

- 主标题不超过两行；
- 正文行宽控制在60—75个中文字符；
- 后台表格优先紧凑，正文页面优先舒展；
- 不使用全大写英文做装饰；
- 不使用过多粗体；
- 正文粗体只强调结论和关键动作。

# 四、空间与布局Token

## 4.1 间距

使用8px基础网格：

```text
4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96
```

规则：

- 卡片内边距：24px；
- 小卡片：16px；
- 页面左右边距：桌面64px，平板32px，移动端16px；
- 页面章节间距：64—96px；
- 表单字段间距：20—24px。

## 4.2 宽度

| 区域 | 最大宽度 |
|---|---:|
| 前台内容 | 1200px |
| 阅读页正文 | 760px |
| 任务详情正文 | 880px |
| 参与者中心 | 1280px |
| 管理后台 | 1440px |

## 4.3 圆角与阴影

| Token | 值 |
|---|---|
| 小圆角 | 6px |
| 常规圆角 | 10px |
| 大圆角 | 16px |

阴影只用于：

- 下拉菜单；
- 弹窗；
- 悬浮操作面板。

普通卡片优先使用边框，不使用大阴影。

# 七、任务模块

## 7.1 任务列表

顶部：

- 页面标题；
- 简短说明；
- 搜索；
- 类型筛选；
- 状态筛选；
- 截止时间筛选。

任务卡片必须一眼可见：

```text

所属项目
任务类型
交付物
截止时间
报酬/分配方式
状态
剩余名额
[查看任务]
```

## 7.2 TaskCard状态

- 开放申请：品牌青绿色；
- 即将截止：提醒色；
- 已分配：信息色；
- 已结束：中性色；
- 暂停或取消：风险色或中性色。

## 7.3 任务详情页

页面顺序固定：

1. 任务名称与状态；
2. 任务目的；
3. 交付物；
4. 验收标准；
5. 截止时间；
6. 报酬与版权；
7. AI使用规则；
8. 申请资格；
9. 申请按钮；
10. 常见问题。

关键交互：

- 用户申请前必须勾选任务规则；
- 版权、署名和AI使用必须显式展示；
- 验收标准不得折叠到默认隐藏区域；
- 任务变更后显示版本和变更记录。

# 十一、表单与上传

## 11.1 表单规则

- 标签永远可见；
- 不用placeholder代替字段名；
- 必填项明确标记；
- 错误信息紧贴字段；
- 保存失败不得清空输入；
- 长表单分区，不分成多步向导除非必要。

## 11.2 文件上传

显示：

- 支持格式；
- 单文件上限；
- 总文件上限；
- 上传进度；
- 文件哈希或版本信息；
- AI处理与数据出站提示；
- 版权声明。

任务提交前必须让用户确认：

- 有权提交材料；
- 是否允许AI处理；
- 是否允许匿名形成实验数据；
- 是否允许公开署名。

# 十二、状态与异常交互

## 12.1 加载

- 使用骨架屏；
- 不使用无限旋转超过10秒；
- 长任务显示当前阶段；
- Agent运行显示“已排队／运行中／校验中／待人工审批”。

## 12.2 空状态

空状态必须告诉用户下一步做什么。

错误示例：

> 暂无数据。

正确示例：

> 你还没有参与任务。浏览开放任务并提交第一份申请。

## 12.3 错误

错误必须分为：

- 用户输入错误；
- 权限不足；
- 系统故障；
- Agent故障；
- 数据出站受阻；
- 成本熔断；
- 需要人工裁决。

不得统一显示“系统错误”。

## 12.4 高风险操作

以下动作必须二次确认：

- 驳回交付物；
- 取消任务；
- 修改报酬；
- 修改版权；
- 关闭参与者账号；
- 批准高风险候选；
- 变更Agent权限；
- 撤回公开内容。

确认框必须显示影响对象和后果。

# 十三、响应式规则

## 13.1 断点

```text
Mobile: < 640px
Tablet: 640—1023px
Desktop: 1024—1439px
Wide: ≥ 1440px
```

## 13.2 移动端优先级

移动端必须支持：

- 浏览书籍；
- 浏览与申请任务；
- 查看任务状态；
- 上传交付物；
- 查看反馈；
- 进行简单审批。

管理后台复杂表格允许在移动端降级为卡片列表。

## 13.3 导航

- 桌面端：顶部导航；
- 移动端：折叠菜单；
- 参与者中心移动端：顶部Tab或抽屉；
- 后台移动端：可折叠侧栏。

---

# 十四、无障碍与可用性

最低要求：

- 所有按钮可键盘操作；
- 输入框有label；
- 图标按钮有文字说明或aria-label；
- 颜色不是唯一状态表达；
- 对比度满足常规阅读需求；
- 错误信息可被屏幕阅读器识别；
- 焦点状态清晰；
- 弹窗关闭后焦点回到触发元素；
- 上传进度有文字说明。

---

# 十五、禁止项

Kimi Code在实现中不得自行加入：

- AI聊天窗口；
- 机器人头像；
- 3D青瓷旋转模型；
- 粒子背景；
- 蓝紫渐变；
- 科技大屏；
- 玻璃拟态；
- 大量阴影；
- 首页轮播；
- 自动播放视频；
- 无真实数据的统计数字；
- 用户排行榜；
- Agent排行榜；
