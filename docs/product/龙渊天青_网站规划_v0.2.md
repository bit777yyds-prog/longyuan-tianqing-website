# 一、核心架构裁决

## 1.1 网站与Agent不是两个系统

> **网站和Agent不是两个彼此接入的系统，而是同一本事件总账的两类读写者。**

- 人通过网页创建任务、提交交付物、验收、返工与裁决；
- Agent通过Worker读取待处理事件，执行被授权的工作，把结果作为候选事件写回；
- 审批服务根据权限政策，将候选事件批准、驳回或自动生效；
- 前台、后台、Agent和统计系统都从同一事实历史投影当前状态。

Agent不是挂在网站旁边的聊天机器人，也不另建一套业务数据库。它是组织环上的执行主体。

## 1.2 同一总账不等于无边界写入

Agent默认不得直接改写正式状态。

正确路径：

```text
正式事件 / 人工操作
        ↓
事件总账
        ↓
Agent Job
        ↓
Agent Run
        ↓
候选事件 Candidate
        ↓
人工审批或授权策略
        ↓
正式事件
        ↓
状态投影更新
```

由此形成两层写入：

1. **候选层**：Agent可以写；
2. **正式层**：只能由审批服务按照权限和政策写入。

## 1.3 网站是Agent原生组织的第一参考实现

网站前台看起来仍然只有三个区域：

- 书籍；
- 任务；
- 公司介绍。

但每一次真实操作都同时成为：

- 业务动作；
- 工作凭证；
- Agent触发条件；
- 状态迁移；
- 实验记录；
- 资产形成记录。

# 三、Agent原生运行模型

## 3.1 Agent的三种触发方式

### 事件触发

例：

- 用户提交交付物；
- 新任务发布；
- 任务超过截止时间；
- 一项正式事件被批准；
- 某工作对象进入指定状态。

### 定时触发

例：

- 每晚生成次日任务草案；
- 每周汇总工作对象变化；
- 每季度执行GEO测试；
- 周期性检查未闭合事项；
- 生成备份与一致性报告。

### 人工点按

例：

- 生成本轮切片计划；
- 对交付物执行验收初判；
- 对一本书运行一致性检查；
- 生成任务拆分建议；
- 重跑指定版本的分析。

## 3.2 Agent首期任务类型

首期只实现少量、高价值、可人工验收的Agent能力：

1. **交付物验收初判**
   - 检查格式、字段、数量和明显缺漏；
   - 输出候选结论，不作最终验收。

2. **任务拆分草案**
   - 根据项目目标生成任务候选；
   - 由负责人编辑后发布。

3. **内容与数据分析**
   - 对账号、视频、文本或任务数据生成结构化候选记录。

4. **周期汇总**
   - 生成日报、周报、未闭合事项和异常候选。

5. **GEO测试**
   - 按预设问题测试外部搜索和模型是否正确理解品牌。

## 3.3 Agent首期禁止事项

- 独立决定人员报酬；
- 独立驳回参与者；
- 独立处分、封禁或评价人格；
- 直接删除正式事件；
- 静默修改作品、任务、交付物或规则；
- 自行扩大权限；
- 自行变更受控词表、验收政策和模型配置。

# 四、授权等级

## 4.1 建议授权分级

| 等级 | 权限 | 典型用途 |
|---|---|---|
| **A0 观察** | 只读总账，输出报告，不写候选 | 查询、统计、分析 |
| **A1 候选** | 可写候选表，必须人工批准 | 验收初判、任务草案 |
| **A2 条件执行** | 对低风险类型可自动批准，异常必须转人工 | 格式校验、重复检测 |
| **A3 授权自治** | 指定事件类型可自动生效，事后抽检 | 成熟、低风险、可回滚任务 |
| **A4 禁止首期** | 涉及人员权利、资金、法律与不可逆外部发布 | 首期不开放 |

## 4.2 代码落地

权限不是抽象宣言，而是配置数据：

```text
agent_id
agent_version_id
allowed_job_types[]
allowed_candidate_types[]
autonomy_level
auto_approve_conditions
requires_human_review
post_audit_sample_rate
max_cost_per_run
max_runs_per_hour
effective_from
effective_until
```

# 五、事件总账

## 5.1 总账原则

事件总账是系统事实历史的物理载体：

- 只增不改；
- 每条事件有唯一ID；
- 每条事件记录发生时间与入账时间；
- 每条事件记录主体、对象、版本、来源和政策；
- 错误通过更正事件处理，不覆盖历史；
- 当前状态由正式事件投影产生。

## 5.2 关键标识

```text
event_id
correlation_id     同一业务流程
causation_id       直接触发本事件的上游事件
idempotency_key    防止重复写入
actor_id
object_id
event_type
occurred_at
recorded_at
payload
policy_version
schema_version
```

## 5.3 四类数据必须分开

1. **事件总账**：已生效事实；
2. **候选事件**：尚待批准；
3. **当前状态投影**：从正式事件计算出的查询视图；
4. **操作审计日志**：谁在后台点了什么。

# 六、任务与工作对象

## 6.1 任务不是工作对象

任务是组织接口；工作对象是被改变的东西。

例：

- 任务：补齐《照此烧造》前十章器物表；
- 工作对象：《照此烧造》器物索引；
- 状态迁移：未建立 → 已抽取 → 已复核 → 已冻结。

## 6.2 所有正式工作必须关联任务

原则上，员工、参与者、Agent和外部组织的正式工作都应关联：

- 项目；
- 任务；
- 工作对象；
- 规则版本；
- 输入；
- 交付物；
- 验收主体。

非任务化的紧急操作也必须事后补录为事件和工作对象变化，不得只留在聊天中。

# 八、首期容器架构

## 8.1 五个核心容器

```text
Caddy / Nginx
      ↓
Web Application
      ↓
PostgreSQL Event Ledger
      ↑
Agent Worker
      ↑
Scheduler / Cron
```

1. **Web Application**
   - 前台三区；
   - 参与者中心；
   - 管理后台；
   - API；
   - 审批服务。

2. **PostgreSQL**
   - 业务表；
   - 事件总账；
   - 候选与审批；
   - Agent登记与运行记录；
   - 审计日志。

3. **Agent Worker**
   - 领取Job；
   - 调用模型适配层；
   - 保存运行记录；
   - 写入候选事件；
   - 不直接改正式状态。

4. **Scheduler**
   - 创建周期Job；
   - 触发汇总、检查、GEO测试和备份。

5. **Caddy/Nginx**
   - 域名入口；
   - HTTPS；
   - 反向代理；
   - 基础限流。

## 8.2 单体优先

首期明确拒绝：

- Kubernetes；
- 微服务拆分；
- Kafka/RabbitMQ集群；
- 多数据库；
- Agent独立后台；
- 每个模型一套代码；
- 复杂工作流引擎。

任务队列首期直接使用PostgreSQL，Worker通过`FOR UPDATE SKIP LOCKED`安全领取。

# 九、多模型适配层

## 9.1 适配原则

Worker不直接把任务写死到某个模型。

配置关系：

```text
job_type
→ agent_version
→ model_provider/model_name
→ prompt_version
→ output_schema
→ validator
→ autonomy_policy
```

## 9.2 版本纪律

每次Agent运行必须记录：

- Agent版本；
- 模型服务商；
- 模型名称；
- Prompt版本；
- 输入哈希；
- 输出哈希；
- Token使用；
- 费用；
- 延迟；
- 是否人工修改；
- 最终审批结果。

模型或Prompt变化即新版本，不覆盖旧版本。

## 9.3 安全凭证

API密钥：

- 不进入代码仓库；
- 不进入事件payload；
- 不进入Agent输出；
- 本地放`.env`；
- 生产优先使用云密钥管理；
- 定期轮换；
- 泄露后立即撤销并记录安全事件。

# 十、备份与恢复

## 10.1 宪法级义务

> **架构可以寒酸，备份必须庄严。**

最低要求：

- PostgreSQL每日逻辑备份；
- 云盘或数据库每日快照；
- 备份同步到异地对象存储；
- 原始文件与交付物单独备份；
- 每月至少一次恢复演练；
- 备份失败必须生成正式异常事件。

## 10.2 恢复目标

首期建议：

- RPO：不超过24小时；
- RTO：不超过4小时；
- 关键事件总账可通过WAL或托管数据库能力进一步降低RPO。

# 十一、部署与法域

## 11.1 大陆部署候选

若使用中国大陆服务器对外提供网站服务，首期按大陆网站合规路径设计：

- 使用杭州公司主体；
- 域名与主体关系清晰；
- 办理ICP备案；
- 公安备案、内容许可或其他手续根据实际业务另行判断；
- 前台不开放直接面向公众的通用生成式AI聊天入口。

## 11.2 Agent后台不等于自动豁免

后台Agent、人工终审和不提供公开聊天交互，通常可以降低“直接向公众提供生成式AI交互服务”的产品暴露面，但不能仅凭架构断言无需任何生成式AI备案、登记、模型信息公示或生成内容标识义务。

正式上线前应根据以下事实分类判断：

- 是否向境内公众直接提供生成能力；
- 是否直接调用已备案模型并形成公开功能；
- 是否具有舆论属性或社会动员能力；
- AI内容是否直接展示或发布；
- 是否需要显式或隐式标识；
- 使用的模型备案/登记状态；
- 网站、任务系统和内容业务对应的其他许可。

本规划只冻结技术边界，不替代专项法律意见。

# 十三、首批验收指标

## 13.1 业务指标

- 任务申请成功；
- 提交成功；
- 验收与返工闭环；
- 历史版本可查；
- 负责人无需借助微信完成任务闭环。

## 13.2 Agent指标

- Job不重复执行；
- 运行失败可重试；
- Agent无法越权写正式状态；
- 每次运行能追溯模型与Prompt版本；
- 候选审批结果可统计；
- 人工修改前后有差异记录。

## 13.3 总账指标

- 事件不可更新或删除；
- 更正通过新事件实现；
- 当前状态能回指事件；
- 同一流程有correlation_id；
- 重复请求被idempotency_key拦截；
- 备份可以恢复。

# 十五、最终定位

首期网站表面上仍然是：

> **龙渊天青的作品与开放任务平台。**

但它的真实技术性质是：

> **一套以事件总账为核心、让人和Agent共同执行任务、由权限和审批控制正式状态的Agent原生组织运行系统。**

Agent不是外挂功能。网站从第一天就是它的工作场。
