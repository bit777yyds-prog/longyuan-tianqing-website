# 一、总裁决

> **Agent原生不是让模型获得数据库权力，而是让Agent成为事件环上的受控工人。**

系统须同时满足：

- 模型不直接执行工具；
- Worker执行工具并受权限约束；
- Agent语义结果只进入候选层；
- 确定性运行故障通过受限系统通道进入正式总账；
- 外部内容永不自动批准；
- 敏感对象在出站前被字段化检查；
- 重放不重新调用模型；
- 版本变化不覆盖历史。

---

# 二、P0：开工前必须落实

## P0-1　正式事件与候选事件隔离

Worker不得写正式事件。Agent语义输出只写候选，审批服务写正式总账。

## P0-2　事件总账只增不改

正式事件禁止UPDATE/DELETE；错误通过更正事件处理。

## P0-3　数据出站分级

工作对象与交付物增加`egress_class`。`forbidden`拒绝出站并生成异常事件。

## P0-4　重放语义

Replay使用存档输出；重新调用模型是Rerun。二者必须拥有不同运行类型和记录。

## P0-5　Prompt注入与外部内容永不自动批准

三层防线：

1. 外部内容以不可信数据块包裹；
2. 输出过Schema与语言校验；
3. `contains_external_content=true`时数据库与审批服务均禁止自动批准。

## P0-6　成本熔断与失败入账

费用超限、模型失败、dead-letter、输出校验失败、出站阻止均必须在正式事件总账可见。

# 三、P1：首轮内部试运行前完成

## P1-1　模型备案与处理信息字段

记录服务商状态、备案或登记号、核验日期与数据处理区域。

## P1-2　影子模式

第二模型跟跑只写Run，不写Candidate，用于离线比较和权限升级证据。

## P1-3　输出语言策略

语言属于Prompt/Agent版本；中文任务增加显式语言指令、中文Schema描述和CJK比例校验。

## P1-4　版本不可热改

Prompt、Agent与模型配置语义不可原地修改。变化创建新版本。

## P1-5　出站最小化与清单

每次调用产生`egress_manifest`，记录发送了哪些对象、最高等级、模型和处理区域。

## P1-6　恢复与证据回放

备份恢复后，使用历史Run输出和事件重建状态；不得因重放再次产生模型费用或不同结论。

# 四、第一条真实判例：中文任务输出英文反馈

## 事实判断

该问题首先属于Prompt/Agent版本，而不是单纯模型配置：

- Prompt没有明确声明自然语言输出为简体中文；
- Schema键和描述可能以英文暗示输出语域；
- 输入材料可能以英文或数字为主；
- 模型更换可能暴露原Prompt的欠约束。

## 正确处理

1. 查询候选关联的`source_run_id`；
2. 核对`prompt_version_id`、模型与raw output；
3. 新建Prompt版本，不热改旧行；
4. 新建Agent版本；
5. 旧候选通过审批修改或驳回，不删除；
6. 添加语言校验；
7. 记录该裁决进入规则库。

## 不得做

- 直接改旧Prompt文本；
- 删除英文候选；
- 将原因无证据地归咎于模型；
- 仅靠人工每次手改；
- 让非中文候选自动发给参与者。

# 六、最终解释

这些约束并非一般意义上的“工程加固”，而是制度条文的数据库形态：

| 制度原则 | 技术形态 |
|---|---|
| 权限先于执行 | Candidate/Approval/Event三层 |
| 必要保护 | `egress_class` |
| 不确定性入账 | 失败与dead-letter正式事件 |
| 可回滚、可重放 | Replay使用历史输出 |
| 编译器版本即政策 | Prompt/Agent/Model版本不可热改 |
| 人不可被自动裁决 | 外部内容和人员权益永不自动批准 |
| 抽检即校准 | Shadow模式与人工修改率 |

> **制度让系统在事故发生之前，就知道应该在哪里加字段、加约束和加审批。**
